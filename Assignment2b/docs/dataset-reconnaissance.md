## 1. Dataset Overview

The **C-MAPSS (Commercial Modular Aero-Propulsion System Simulation)** dataset is a benchmark engineering dataset for data-driven prognostics, condition monitoring, and Remaining Useful Life (RUL) estimation in gas turbine machinery.

Generated by the **NASA Prognostics Center of Excellence (PCoE)** at NASA Ames Research Center in collaboration with NASA Glenn Research Center and GE Global Research, the dataset simulates run-to-failure degradation trajectories for a fleet of large commercial turbofan engines in the **90,000 lb thrust class**. 

The dataset was originally released as the official challenge dataset for the **Prognostics and Health Management (PHM) Data Competition at PHM'08** (First International Conference on Prognostics and Health Management, Denver, CO, October 2008).

Each trajectory simulates an engine starting from a nominal healthy state (with varying initial manufacturing wear) and developing an unannounced degradation fault that progressively deteriorates until a system failure criterion is breached.

## 6. Grain Observations & Contiguity Analysis

Programmatic verification of the data across all variants established the following data structure properties:

1. **Grain Definition**: Exactly **one record per engine unit per operational flight cycle**:
   $$\text{Grain} = (\text{unit\_number},\; \text{time\_in\_cycles})$$
2. **Key Uniqueness**: The composite tuple `(unit_number, time_in_cycles)` is **100% unique** across all training and test files. Zero duplicate snapshots exist.
3. **Contiguous Unit Identifiers**: In every training and test dataset, unit numbers are strictly contiguous integers ranging from $1$ to $N_{\text{engines}}$ without a single missing unit.
4. **Strict Cycle Continuity**:
   - Every single engine trajectory in both training and test sets begins at **`cycle = 1`**.
   - Cycle increments strictly by $+1$ on each subsequent row without gaps, skips, or out-of-order timestamps ($\Delta \text{cycle} \equiv 1$).
5. **No Null or Missing Values**: Zero `NaN` or missing values exist within the tabular data matrix across all four datasets when parsed with standard whitespace regex (`sep=r'\s+'`).

## 7. Train / Test / RUL Structure

The relationship between the training sets, test sets, and RUL truth vectors is structured as follows:

```
[TRAINING ENGINES]
Cycle 1 ───────────────────────────────► Cycle C_fail (Failure Threshold H = 0)
(Complete Run-to-Failure; Full degradation history observed)

[TEST ENGINES]
Cycle 1 ────────────────► Cycle C_cutoff  · · · · · · · · · · · · · ► [True Failure]
(Truncated observation)                   └────── True RUL ─────────┘
                                          (Supplied in RUL_FD00x.txt)
```

1. **Training Set (`train_FD00x.txt`)**: 
   - Trajectories represent **un-truncated run-to-failure simulations**.
   - Each engine runs until the calculated Health Index reaches zero ($H(t) = 0$).
   - The final recorded cycle for a training engine represents its catastrophic/functional end-of-life cycle ($C_{\text{fail}}$).
2. **Test Set (`test_FD00x.txt`)**:
   - Trajectories represent **censored operational histories**.
   - The simulation trajectory was intentionally truncated at an arbitrary operational point prior to system failure ($C_{\text{cutoff}} < C_{\text{fail}}$).
3. **Ground Truth RUL Files (`RUL_FD00x.txt`)**:
   - A single-column text file containing exactly $N_{\text{test}}$ integers.
   - Row $i$ corresponds directly to test engine unit $i$.
   - Represents the exact number of remaining operational cycles from the last recorded cycle in the test file until system failure:
     $$C_{\text{fail, test}} = C_{\text{cutoff, test}} + \text{RUL}_{\text{true}}$$
4. **Implied Lifetime Parity**: Programmatic analysis confirms that the distribution of implied total lifespans for test engines ($C_{\text{cutoff}} + \text{RUL}$) closely mirrors the empirical failure cycle distribution of the training engines.

## 8. Documented Semantics

The following engineering facts are explicitly established by the official NASA documentation and published literature:

* `[DOCUMENTED FACT]` **Physical System**: The simulated engine is a large commercial two-spool turbofan engine modeled in MATLAB/Simulink using C-MAPSS, representing a 90,000 lb thrust class propulsion system.
* `[DOCUMENTED FACT]` **Operational Cycle**: One cycle corresponds to one complete flight profile snapshot recorded at cruise conditions.
* `[DOCUMENTED FACT]` **Degradation Physics**: Degradation is modeled as exponential efficiency loss ($e$) and flow capacity loss ($f$) within engine rotating components:
  $$h(t) = 1 - d - \exp\{a \cdot t^b\}$$
* `[DOCUMENTED FACT]` **Failure Criterion**: The overall Health Index is defined as the minimum of four operational margins:
  $$H(t) = \min(m_{\text{Fan}},\, m_{\text{HPC}},\, m_{\text{HPT}},\, m_{\text{EGT}})$$
  Failure is declared when $H(t) \le 0$, representing safety limit violation (15% reduction in stall margins or ~2% EGT margin exceedance).
* `[DOCUMENTED FACT]` **Process & Sensor Noise**: Each engine begins with normal manufacturing variation (up to 1% initial deterioration). Noise is non-Gaussian mixture noise filtered through thermo-mechanical system dynamics, combined with superimposed measurement noise.
* `[DOCUMENTED FACT]` **Evaluation Metric**: The official PHM'08 scoring function evaluates RUL prediction error $d = \hat{t}_{\text{RUL}} - t_{\text{RUL}}$ with an asymmetric exponential penalty that penalizes late predictions (optimistic, hazardous) much more severely than early predictions (conservative, costly):
  $$s = \sum_{i=1}^{n} \left( \exp\left\{-\frac{d_i}{10}\right\} - 1 \right) \quad \text{for } d_i < 0 \quad (\text{Early Prediction})$$
  $$s = \sum_{i=1}^{n} \left( \exp\left\{\frac{d_i}{13}\right\} - 1 \right) \quad \text{for } d_i \ge 0 \quad (\text{Late Prediction})$$

## 9. Unknown Semantics & Gaps

The following aspects are **not documented** in the official release and must be recorded as `UNKNOWN`:

* `[UNKNOWN]` **Physical Time Duration per Cycle**: The exact flight duration (hours, minutes) represented by a single cycle is unstated.
* `[UNKNOWN]` **Specific Real-World Engine Make/Model**: C-MAPSS models generic 90,000 lb thrust class physics (representative of engines like GE90, PW4000, or Trent 800), but the exact proprietary commercial engine configuration is withheld.
* `[UNKNOWN]` **Intermediate Health Index Trajectories**: While the initial healthy state ($H \approx 1$) and failure point ($H = 0$) are defined, the instantaneous ground-truth health value $H(t)$ at each intermediate cycle is not provided in the raw data files.
* `[UNKNOWN]` **Exact Point of Fault Onset**: The exact cycle at which an engine transitions from normal wear to accelerated fault evolution is not explicitly annotated.
* `[UNKNOWN]` **Financial / Maintenance Cost Matrix**: The dataset does not provide dollar costs for maintenance operations, unscheduled component replacements, flight cancellations, or aircraft-on-ground (AOG) events.

## 10. Potential Data-Quality & Parsing Traps

Reconnaissance revealed critical data-engineering nuances that must be governed during ingestion:

1. `[LIMITATION / FORMATTING TRAP]` **Trailing Space Ingestion Bug**:
   Every record line in all `train_*.txt` and `test_*.txt` files terminates with a trailing space (`" \n"`). If parsed naively using Python's standard delimiter `sep=' '`, pandas reads **28 columns**, creating two phantom columns (indices 26 and 27) that are completely populated with `NaN`.
   * *Resolution Requirement*: All ingestion must utilize whitespace regex `sep=r'\s+'` or `delim_whitespace=True`, producing the clean, expected 26-column matrix without NaNs.
2. `[LIMITATION / ZERO-VARIANCE SENSORS]` **Flatline Sensors Under Single-Condition Operation**:
   In FD001 (Sea Level operation), **6 of the 21 sensors are completely constant** (variance $= 0$, standard deviation $< 10^{-4}$):
   - `sensor_1` ($T_2$): Constant at $518.67^\circ\text{R}$ (Standard Sea-Level Temperature: $59^\circ\text{F} / 15^\circ\text{C}$).
   - `sensor_5` ($P_2$): Constant at $14.62\text{ psia}$ (Ambient sea-level pressure).
   - `sensor_10` (`epr`): Constant at $1.30$.
   - `sensor_16` (`farB`): Constant at $0.03$.
   - `sensor_18` (`Nf_dmd`): Constant at $2,388\text{ rpm}$.
   - `sensor_19` (`PCNfR_dmd`): Constant at $100.0\text{ rpm}$.
   - In addition, `sensor_6` ($P_{15}$) takes only two discrete values ($21.60$ and $21.61\text{ psia}$, $\sigma = 0.00139$).
   * *Operational Impact*: These six channels provide no within-dataset variation under FD001 and therefore cannot discriminate degradation progression within this specific analysis. However, in FD002 and FD004 (multi-condition), these same sensors exhibit significant variance driven by flight regime changes.
3. `[DOCUMENTATION DISCREPANCY]` **Trajectory Count Swapping in `readme.txt`**:
   The official `readme.txt` states:
   > `Data Set: FD004`  
   > `Train trjectories: 248`  
   > `Test trajectories: 249`  
   
   **Programmatic Verification Confirms This Is Inverted**:
   - `train_FD004.txt` contains **249 unique engines** (Units $1 \dots 249$).
   - `test_FD004.txt` contains **248 unique engines** (Units $1 \dots 248$).
   - `RUL_FD004.txt` contains **248 rows**.
   The author of `readme.txt` accidentally swapped the train and test trajectory counts for FD004.
4. `[LIMITATION / NOISE NON-MONOTONICITY]` **Local Non-Monotonicity**:
   Because process noise and simulated between-flight maintenance are superimposed, sensor trends are not strictly monotonic on a cycle-to-cycle basis. Any data-driven reasoning must account for high-frequency signal volatility.

For an initial Forward Deployed Engineering assessment and foundational data modeling exercise, **FD001** is strongly recommended as the primary starting variant.

## 14. Evidence Behind the Recommendation

1. **Isolation of Physical Degradation from Operational Regime Shifts**:
   In FD002 and FD004, sensor measurements fluctuate dramatically as the aircraft cycles between 6 flight regimes (e.g., Sea Level vs. 42,000 ft cruise), where substantial sensor variance is driven by altitude and Mach changes rather than component wear. In contrast, **FD001** reduces operating-condition variation relative to the multi-condition subsets, making it a simpler single-condition setting for examining sensor behavior across simulated degradation trajectories without complex multi-regime normalization.
2. **Deterministic Single Failure Mode**:
   FD001 isolates a single failure mode: High-Pressure Compressor (HPC) degradation. This ensures that degradation signatures across all 100 engines follow a coherent physical degradation path, avoiding competing failure modes where fan degradation and compressor degradation exhibit conflicting sensor dynamics (as in FD003 and FD004).
3. **Statistically Significant Fleet Size**:
   With **100 training engines (20,631 cycles)** and **100 test engines (13,096 cycles)**, FD001 provides sufficient sample size for fleet-wide statistical distributions, validation gates, and outlier analysis, while remaining computationally agile and transparent.
4. **Literature & Industry Benchmark**:
   FD001 is universally recognized as the foundational baseline in industrial prognostics research. Beginning with FD001 establishes an uncorrupted baseline before introducing operating regime complexity.
